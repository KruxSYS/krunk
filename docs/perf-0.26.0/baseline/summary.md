# Baseline: Krunk 0.25.5 vs Chrome 157 vs Edge 156 (replay corpus, Windows VM)

Status: **DRAFT**. The tables are generated by `scripts/perf/load-summary.py` once the main pass
and the fill pass are in; the headline and noise sections are filled in from that output.

## Method
- **Binary check:** krunk-a/krunk-b ran `app260h`, built 00:16 UTC from c15ab23 + the uncommitted harness edits only. f9ab3f6 (login.js), 602f01e, ae4f6d2 and later came after. No rerun needed (`notes.md`).
- **Machine:** the Windows 11 test VM (4 vCPU, no GPU), display 1280×800, every browser
  maximized.
- **Corpus:** 9 pages recorded once with Chrome 157 from the VM (`../corpus/`, `corpus.wprgo`,
  1408 responses from 78 hosts):
  - news (theguardian.com/international);
  - spa (react.dev/learn);
  - search (Bing results);
  - shop (an IKEA product page);
  - youtube (a watch page);
  - wiki (Wikipedia "Web browser");
  - ads (Allrecipes);
  - docs (MDN Performance API);
  - hn (Hacker News).
- **Serving:** replayed by Web Page Replay behind a 40 ms RTT shim (`lshim`). Every host is mapped
  to it with `--host-resolver-rules` (Krunk: `KRUNK_HOST_RULES` in the harness build). The private
  test CA is trusted only while a pass runs.
- **QUIC:** off for all three browsers: Chrome/Edge get `--disable-quic`, Krunk has it as an extra
  flag in its base profile.
- **Builds:**
  - **krunk-a and krunk-b:** the same binary twice (the A/A pair): `app260h`, the harness build
    of c15ab23 (0.25.5 + `perf-harness` only, no 0.26.0 fix code; `notes.md`). `krunk` is both
    pooled (10 runs per cell).
  - **chrome:** Chrome 157.0.8103.39.
  - **edge:** Edge 156.0.4314.58.
  - Each session starts from a fresh profile: Krunk from `lp-base` (filter lists fetched, no
    session), Chrome/Edge from an empty `--user-data-dir`. Then 8 s idle.
- **Scenarios** (`scripts/perf/README-load.md`):
  - typed: cold = the first omnibox navigation after start; warm = the same URL typed again in
    that session;
  - link: link = a click on a full-window link from a local page; back (Alt+Left to that page);
    forward (Alt+Right to the corpus page again).
- **Runs:** 5 per browser, page and scenario, interleaved page by page with the browser order
  rotated each run.
- **Metrics:** ms from the input (kinput's injection time, on the clock of
  `performance.timeOrigin`):
  - nav = navigation start, i.e. the browser's hand-off;
  - TTFB = `responseStart`;
  - FCP;
  - LCP (the last candidate, 3 s after `load`);
  - DCL = `domContentLoadedEventEnd`;
  - load = `loadEventEnd`;
  - back/forward-cache restores: show (pageshow) and frame (two rAFs after it).
- **Statistics:**
  - median and p90 (nearest rank) per page;
  - corpus value = the median over the pages of the per-page value;
  - **headline** = per page, the cold and warm typed loads pooled, then the median over pages.
    This is the plan's "corpus median LCP" (cold + typed).
  - Timed-out and error rows never enter a median. Incomplete sessions were rerun in a fill
    pass, whose sessions replace the main pass's (`load-summary.py` with both dirs).
- **Generated with:**
  ```sh
  python3 scripts/perf/load-summary.py runs/baseline runs/baseline-fill --pool krunk=krunk-a,krunk-b --json baseline/numbers.json
  python3 scripts/perf/load-summary.py runs/baseline-live > baseline/live.md
  ```

## Bias rule for the before/after comparison
- Each of Krunk's cold typed cells is counted as one of:
  - **measured in the main pass**;
  - **failed in the main pass, measured in the fill pass** (the fill session replaces the failed
    one);
  - **still missing after the fill**.

  The numbers go in the table below.
- A page and scenario that is still missing **any** run for Krunk 0.25.5 after the fill is
  excluded from the before/after LCP comparison, on **both** sides (0.25.5 and 0.26.0), and from
  the comparison with Chrome and Edge. It is listed by name.
- Reason: a failed cold load that was simply dropped would leave 0.25.5's median made only of the
  runs that worked. If 0.26.0 then fixes the failure (F-keys), its runs include the formerly
  failing ones, which may be the slower loads, and the comparison would be skewed in either
  direction.
- The fill pass reruns these sessions under the same conditions: same binary, fresh profile, same
  interleaving rule. Fill-pass loads count as normal runs.

| Krunk cold typed cells | krunk-a | krunk-b |
|---|---|---|
| expected (9 pages × 5 runs) | 45 | 45 |
| measured in the main pass | 18 | 21 |
| failed in the main pass | 23 | 20 |
| measured in the fill pass | 0 | 1 |
| still missing (excluded on both sides) | 23 | 19 |

**If the fill pass loses keys again (F-keys confirmed and frequent):**
- Excluding every affected page would drop most of the cold scenario.
- Proposed fallback, for the director to decide: one more cold-typed pass for **all** browsers with
  the driver waiting until the address bar has the focus before it types. For Krunk the shell's
  `document.activeElement` must be `#address`; for Chrome/Edge a fixed 1 s pause after Ctrl+L.
- That pass measures load speed without the focus race, the same way for all three.
- The race itself is reported separately as a correctness metric: the share of cold typed loads
  that never started, before and after F-keys. It is not hidden.

## Missing cells and why
Lists per cell: `cells.md`. Every page misses at least one cold run, so the bias rule would exclude
the whole cold scenario: the 0.25.5-vs-0.26.0 cold comparison uses the measured cells only and is
marked biased; warm and link are complete. The focus-waiting fallback pass was not run (turn
budget); 0.26.0 fixes the cause instead (F-keys), so its own cold cells are complete.
- **Main pass:**
  - 3 cells, krunk-b news run 1 link/back/forward: the replay CA was removed mid-pass by an
    interrupted host script (`notes.md`);
  - N Krunk cold typed cells: the typed URL never reached the address bar (`notes.md`, "second
    reading").
- **Fill pass:** which of them came back, and which are still missing, with the reason.

## Cold-typed timeouts: verdict
`lost-keys.md`: Krunk cold typed never started in 94 of 134 tries (krunk-a 50/68, krunk-b 44/66);
warm 4/134; Chrome and Edge 5/45 each (all "unknown", fill-pass link cells). In the 51 Krunk cases
with diagnostics, **every key went to the page** (`keys` = URL length + Enter), the address bar
stayed empty and neither shell had the focus: the Ctrl+L focus move doesn't take on the first
Ctrl+L after start. **Product bug → F-keys confirmed** (6d41a90: keys reaching the page within 1 s
of Ctrl+L go to the address bar).
